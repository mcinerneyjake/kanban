# Fixture corpus — the reproducible half of the retrieval eval

`corpus/` holds 61 synthetic tickets. They exist so the retrieval eval has a corpus that **survives a
checkout**: the real board lives in `tickets/`, which `.gitignore:12` excludes, so a fresh clone has
no board at all and the eval aborts on an empty index before any embedder is contacted
(`tkt-07fab923fcbd`).

Two properties matter, and both are load-bearing:

- **Committed.** `.gitignore:12` is `tickets/` with no leading slash, so it matches a directory of
  that name at *any* depth — a corpus placed under one is present for its author and silently absent
  for everyone else. This directory is called `corpus/` for that reason, following the same dodge as
  `test-support/demo-board/`. `fixtureCorpus.test.ts` asserts the files are in the git index rather
  than merely on disk, so the trap cannot come back quietly.
- **Synthetic.** Nothing here is copied from the real board. This repository is public, and the board
  is not.

## The distractor design

Every golden anchor has **three or more deliberate near-misses** in the corpus: tickets that share its
vocabulary and subject while answering a different question — "retry failed webhooks" against "log
webhook failures", "verify webhook signatures", "a webhook delivery dashboard".

That is the point of the corpus, and it is not decoration. Recall sensitivity comes from distractor
*quality*, not corpus size: the 2026-07-24 board baseline scored recall@5 = 1.000 over 509 vectors,
a saturated number that cannot show a regression. Unrelated documents never rank top-5, so adding
thousands of them would not have changed that.

**Where the headroom actually is (measured 2026-09-09):**

| metric | baseline | headroom |
|---|---|---|
| recall@1 | 0.667 | wide, both directions — the metric to watch |
| MRR | 0.833 | wide |
| recall@5 | 1.000 | **saturated** — a coarse tripwire only |

recall@5 is still at the ceiling and honestly could not be moved without engineering for the metric:
dropping an anchor below rank 5 needs five stronger competitors for one query, and writing them to
force a miss is the mirror image of tuning a query to force a hit, which `golden.ts` forbids. It is
kept in the baseline because it is free and *can* fall if an embedder swap goes badly. **Read recall@1
and MRR as the signal.**

Deepening the four thinnest subject areas took recall@1 from 0.917 (48 docs) to 0.667 (61 docs). Four
anchors now rank @2 behind a near-miss; each was checked by hand, and in three of the four the winner
is clearly *not* a better answer to the query. The fourth — a bundle-size query where a build-budget
ticket outranks the lazy-loading one — is genuinely ambiguous and was left as a fair miss.

**Misses are the finding, not a bug to hand-fix.** If a pair looks wrong, fix the pair or the corpus.
Never reword a query to recover a hit.

## The negative control threshold is measured, not guessed

`goldenFixture.ts` sets `maxTopScore: 0.42`. Measured 2026-09-09 against this corpus with
`qwen3-embedding-0.6b`: three independent no-answer queries topped out at **0.376 / 0.350 / 0.265**,
while the weakest *true* golden match scored **0.469**. 0.42 sits in that ~0.093-wide gap.

The first pass guessed 0.50 — which is **above** the weakest real match, so it would have waved
through a false hit scoring better than a genuine one. That is precisely the failure the control
exists to catch, and only measuring found it. **Re-derive the threshold whenever the corpus or the
embedding model changes**; those numbers are true only for that pairing.

## Running it

```bash
npm run eval:retrieval -- --fixture             # score the corpus, compare to baseline.json
npm run eval:retrieval -- --fixture --record    # ... and rewrite baseline.json from this run
npm run eval:retrieval                          # score the live board (real, not reproducible)
```

Needs a local OpenAI-compatible embeddings endpoint (`EMBED_BASE_URL`, `EMBED_MODEL`). CI has none,
which is why **no workflow runs the scored eval** — the ticket's "second blocker", still open. What
CI does run is `fixtureCorpus.test.ts`, which needs no embedder and pins the half that the gitignore
defect actually broke.

`--fixture` pins both `TICKETS_DIR_OVERRIDE` and `EMBED_CACHE_PATH` to this directory. The second is
a guard, not tidiness: the build prunes the embedding store to the corpus it just embedded, so a run
that inherited an ambient `EMBED_CACHE_PATH` would delete every board vector in the embedder's
namespace.

## baseline.json

Generated by `--record`, never hand-edited. It carries provenance alongside the metrics — corpus
name, size, search depth, embedding model, endpoint, both instruction prefixes, and **content hashes
of the corpus and of the golden set** — and the comparison **refuses** rather than printing a delta
when any of those differ: a score measured with a different embedder is a different experiment, not
a regression.

The two hashes are there because a count cannot see the edits that matter most. Rewording a ticket
body, rewording a query, re-pointing an anchor or moving the negative threshold all leave
`corpusSize` at 61 while changing what is being asked.

A **missing** baseline is fine and reads as "none recorded yet". An **unreadable or malformed** one
is fatal — it is not the same state, and treating it as absent would report an uncompared run over a
file that exists and then offer to overwrite it. `--record` is the documented repair path and stays
available in that case, which is the only reason reading the file is not fatal unconditionally.

Drift is **reported and exits 0**. It is not a gate, by design — a recall number moving is a prompt
to look, and making it fail the build would redden every embedding experiment. The loud half is
`assertRetrievalInstruments`, which aborts before a metric exists if an instrument cannot be trusted.
